# Residdy · кабінет партнерів і спеціалістів

Один Next.js застосунок із двома робочими просторами. Роль визначається сервером після входу: `PARTNERS` відкриває компанії й рекламу, `SPECIALISTS` — консультації, розклад, бронювання та відгуки.

## Запуск

Потрібен Node.js 20.9+ (підтримуваний LTS) та npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Відкрийте **http://localhost:3002**. Залежності вже встановлено в поточній робочій папці.

`NEXT_PUBLIC_API_URL=http://localhost:7777` узято з локального налаштування менеджерського фронтенду. `.env.local` вже створено з цією адресою. За потреби змініть її на адресу запущеного API. Сам `residdy_backend` без змінних середовища слухає порт 3000. Адреса API вбудовується у клієнт під час збірки; після зміни production-адреси перебудуйте застосунок. Бек має дозволяти origin цього фронтенду через CORS.

```bash
npm run build
npm start
```

Створення партнерських і спеціалістських акаунтів виконує менеджер через наявну CRM. Для входу використовуйте такий акаунт, підтверджений кодом із листа. У цьому кабінеті немає публічної реєстрації: відповідних прав у беку немає.

## Можливості

**Спільні:** вхід, підтвердження акаунта і повторний код, відновлення пароля, особистий профіль, аватар, зміна пошти та пароля за кодом, вихід, світла/темна тема, десктопна оболонка від 1080px, як у менеджерській CRM. Огляд показує кількості записів із API. Підтримуються стани завантаження, порожні списки, помилки, повтор запиту, серверна пагінація й фільтри.

**Партнер:** створення та редагування власних компаній, контакти, описи чотирма мовами, соціальні посилання, логотип і головне фото; перевірка заповнення перед публікацією; публікація та зняття з публікації. Створення та редагування банерів із зображенням, заголовками й підзаголовками чотирма мовами, форматами, посиланням і лімітом показів; статус модерації, причина відхилення, покази, кліки й CTR. Активні та завершені банери доступні для перегляду.

**Спеціаліст:** контакти й професійний профіль, мови, спеціалізація, досвід, освіта, сертифікати; власні консультації, категорії, ціни PLN, тривалість і чотири мовні версії; статуси та архівування. Тижневий календар і список слотів, додавання, редагування й скасування вільного часу. Перегляд власних бронювань, запитів клієнтів, авторизоване скачування файлів, посилання на готову зустріч; опубліковані відгуки.

## Архітектура

Стек і токени оформлення перенесено з `../residdy_managers_crm`: Next.js 16 App Router, React 19, TypeScript strict, SCSS Modules, TanStack Query 5, Lucide. AppShell, Header, Sidebar, екран входу, UI та базові компоненти форм перенесено з менеджерського фронтенду. SCSS оболонки, хедера, меню, форм, таблиць та огляду збігається з джерелом; використовується той самий Inter. Відрізняються доступні розділи, дані сесії та API-операції. Не потрібні тут менеджерські модулі й залежності не перенесено.

- `src/api` — спільний HTTP-клієнт, помилки, токен і залежні типи моделей; авторизаційні операції й завантаження сторінок.
- `src/shared/providers`, `auth`, `hooks`, `guards`, `query`, `theme` — окремі провайдери, контекст сесії, перевірки доступу, кеш та тема, за структурою менеджерського фронтенду.
- `src/shared/styles` — токени та SCSS-міксіни менеджерського фронтенду.
- `src/components/layout-components` — AppShell, Header, Sidebar і Page з менеджерської CRM.
- `src/components/auth-components`, `theme-components`, `form-components`, `ui` — перенесені компоненти входу, теми, полів, селекторів, кнопок і станів.
- `src/features/portal` — ресурсні схеми та рольова конфігурація; `components` — сторінки, форми, календар, деталі, профіль і безпека.
- `src/app` — публічні auth-маршрути та `(private)/main/[[...segments]]` із перевіркою ролі перед створенням сторінки ресурсу.
- `tests` — контрактні й браузерні перевірки з ізольованими API-відповідями.

Старі `/workspace/*` посилання перенаправляються на `/main/*`.

Детальний аудит контрактів і меж: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Перевірки

```bash
npm test
npm run typecheck
npm run lint
npm run format:check
npm run build
npx playwright install chromium
npm run test:browser
```

Браузерні тести працюють у Chromium, запускають окремий dev-сервер на 3102 і `.next-test`, перехоплюють API-запити. Вони не використовують справжніх облікових даних і не надсилають листи, публікації чи зміни до реального бека. Production-збірка використовує `.next` та ваш `.env.local`.

Для фактичної роботи потрібні запущений бек, його база, сховище файлів та поштовий сервіс. Вхід із реальним партнером/спеціалістом не перевірявся: облікові дані не надані. Фронтенд не містить демонстраційних записів або прихованого режиму обходу авторизації.

Сусідні репозиторії використовувались лише для читання. Усі зміни знаходяться тут.
